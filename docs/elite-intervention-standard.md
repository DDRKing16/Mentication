# Mentication Elite Intervention Standard

Version 1.0 — governing design standard for every intervention in Mentication.

## 1. Definition

An elite intervention is a focused psychological experience that helps the user create one useful change in state, perspective or action with minimal friction. It combines an evidence-informed mechanism, a memorable interactive metaphor, honest adaptation and a clear route onwards.

It is not an article, worksheet, generic meditation, productivity timer, decorative animation or collection of tips.

An intervention is elite only when it is:

- **Mechanism-led:** every screen serves the intended psychological process.

- **Immediately usable:** the user reaches the core mechanism within approximately ten seconds wherever safety permits.

- **State-aware:** it checks only the factors that materially change what should happen.

- **Agency-preserving:** the user can edit, skip, reduce, stop or choose another route.

- **Honest:** completion never requires the user to feel better, and uncertainty or no change remain valid outcomes.

- **Memorable:** it has one distinct material, motion and interaction identity.

- **Connected:** it can hand the user to another mechanism without losing relevant context.

- **Accessible:** reduced-motion, silent, screen-reader and low-motor-demand routes are first-class experiences.

- **Buildable:** visuals and interaction rules can be implemented responsively rather than being trapped inside static mockups.

## 2. Required intervention contract

Before final visual generation or coding, every intervention must have one approved contract containing the following fields.

| Field | Required definition |
|---|---|
| Name | Final user-facing name with no competing title |
| Primary goal | Calm, Lift, Ground, Focus or Sleep |
| Primary design system | The reusable experience engine it demonstrates |
| Intended state | The specific problem state it is designed to meet |
| Intended change | The smallest useful psychological or behavioural change it seeks |
| Core mechanism | The active ingredient, stated without visual metaphor |
| Entry criteria | When the intervention is a reasonable match |
| Exclusion criteria | When it should route elsewhere or show support |
| First meaningful action | What the user does within approximately ten seconds |
| Core loop | The repeated interaction, if any |
| Adaptations | Immediate, Standard and Supported routes where appropriate |
| Valid outcomes | Complete, partial, unchanged, stopped and support-needed states |
| Handoffs | The next intervention or external support route for each relevant outcome |
| Memory | What may be stored, why, with what consent and how it can be corrected or deleted |
| Signature system | Material, motion verb, spatial behaviour and audio identity |
| Accessibility | Equivalent reduced-motion, silent, screen-reader and tap-based routes |
| Psychoeducation | One or two user-facing lines with an internal evidence record |
| Asset specification | Component-ready assets, states and formats required for implementation |

No intervention proceeds to final asset generation with an incomplete contract.

## 3. Required experience architecture

Every intervention uses the same underlying architecture, although stages may become invisible or collapse when unnecessary.

~~~
ARRIVE
↓
CHECK FIT
↓
BEGIN THE CORE MECHANISM
↓
ADAPT OR CONTINUE
↓
NOTICE WHAT HAPPENED
↓
STOP, SAVE OR HAND OFF
~~~

### 3.1 Arrive

The opening screen must answer, without explanation-heavy copy:

- What is happening here?

- What is the first thing I can do?

- How can I leave?

It contains one dominant action. A distressed or fatigued user must not need to study the interface before beginning.

### 3.2 Check fit

Ask only questions that change the route. Do not place a generic assessment before every intervention.

A fit check is required when the mechanism could be unhelpful or unsafe in a foreseeable state, including:

- acute danger or urgent medical need;

- very high activation before cognitive work;

- pain, dizziness or injury before body-based activation;

- unsafe contact before relational outreach;

- dangerous or clinically inappropriate behavioural experiments;

- genuine need for rest before activation or productivity-oriented action.

The check must occur before the risky activity, not as footer text or a completion branch.

### 3.3 Begin the core mechanism

The first meaningful therapeutic action occurs within approximately ten seconds wherever safety permits. Explanation is delivered progressively around action rather than as a long introduction.

Each screen has one primary psychological job. If removing a screen does not weaken safety, comprehension or the mechanism, remove it.

### 3.4 Adapt or continue

The user can change intensity without restarting. Depending on the intervention, controls may include:

- make it shorter;

- make it easier;

- slow it down;

- use less or more guidance;

- skip this area;

- different route;

- this is not helping;

- stop now.

### 3.5 Notice what happened

Feedback measures the intervention’s mechanism rather than generic happiness or improvement.

Examples:

- breathing comfort rather than calmness;

- available choice rather than urge disappearance;

- thought conviction and uncertainty rather than correct thinking;

- whether attention entered rather than productivity;

- remaining tension rather than total relaxation;

- whether something was contained rather than whether sleep occurred.

Feedback is optional unless required to determine a safe next step.

### 3.6 Stop, save or hand off

The user may finish without saving. Saving must have an articulated future benefit.

Every intervention supports the relevant honest outcomes:

- completed;

- partly completed;

- unchanged;

- could not begin;

- stopped deliberately;

- uncomfortable or worse;

- need another kind of help.

No celebratory animation, positive label or progress claim is triggered by an outcome the user did not report.

## 4. Adaptation levels

Where the mechanism permits, design three routes from the same engine.

| Route | Purpose | Typical form |
|---|---|---|
| Immediate | Smallest useful contact with the mechanism | Approximately 30–60 seconds |
| Standard | Complete default experience | Main evidence-informed sequence |
| Supported | More time, explanation, choice and accommodation | Slower pacing and additional guidance |

Shorter does not mean inferior. Supported does not mean more therapeutic. The best route is the one that fits the user’s present capacity.

## 5. Safety and suitability standard

Safety is a routing function, not a disclaimer.

Every intervention with foreseeable exclusions defines:

1. the relevant condition;

2. how it is checked;

3. what changes when present;

4. the safer route offered;

5. whether any user input carries forward.

Required principles:

- screen before the potentially unsuitable mechanism;

- ask directly and briefly;

- do not diagnose from behaviour or language;

- do not treat genuine protection, rest or withdrawal from danger as avoidance;

- never use reflective tools to challenge delusional/paranoid beliefs, trauma memories, abuse disclosures or immediate danger;

- never recommend unsafe experiments, movement, contact or exposure;

- preserve a persistent exit throughout;

- present appropriate urgent support when the user reports immediate risk.

Mentication does not describe an intervention as treatment for a medical or psychiatric condition unless that claim has been separately approved and supported.

## 6. Handoff standard

A handoff should feel like the mechanism changes while the user’s journey continues.

The receiving intervention should inherit only relevant, consented information, such as:

- the task named in Next Easiest Step;

- the prediction captured in Thought or Fact;

- the safe contact target chosen in Open Channel;

- the current activation level;

- the selected duration or accessibility settings.

Do not repeat a check-in that has just been completed unless the receiving intervention requires a materially different safety question.

Every handoff states:

- why the alternative may fit better;

- what information will carry over;

- whether the user can return;

- what happens if they decline.

## 7. Personalisation and memory contract

Personalisation is based on user-confirmed evidence, not hidden psychological inference.

For every feature described as learning, remembering, ranking or adapting, define:

- what explicit input is stored;

- what is inferred;

- the minimum evidence required before showing a pattern;

- how uncertainty is communicated;

- how the user corrects or deletes it;

- where it is stored and whether it leaves the device;

- how long it is retained;

- what happens when no useful pattern exists.

Preferred wording:

- “Based on what you previously chose…”

- “This has felt more reachable on two previous evenings.”

- “You usually select the shorter route.”

Prohibited wording without direct measurement and proper validation:

- “Your nervous system responds best to…”

- “We detected your motivation increasing.”

- “This always works for you.”

- “The app knows what you need.”

Do not use saved information to pressure completion, maintain streaks or shame inconsistency.

## 8. AI standard

AI output is a draft, hypothesis or option—not a therapeutic verdict.

The user can always edit, reject, skip, regenerate or create their own answer.

AI must not:

- invent facts, memories, evidence, intentions or symptoms;

- determine that a thought is true or false;

- diagnose a distortion, disorder, risk state or relationship;

- recommend unsafe movement, contact, experiments or high-risk reward behaviours;

- imply that generated wording came from the user;

- send messages, create commitments or contact others without explicit confirmation;

- turn uncertainty into false reassurance.

## 9. Psychoeducation and evidence standard

Each intervention receives one or two user-facing lines only.

The wording must:

- explain the mechanism in plain language;

- distinguish evidence for a general method from evidence for the app’s exact pattern;

- use conditional language when findings are mixed;

- avoid claiming guaranteed calm, sleep, motivation, insight or symptom change;

- avoid turning the visual metaphor into a scientific claim.

Every intervention also has an internal evidence entry containing:

- claim supported;

- source or review;

- population studied;

- important limitations;

- date last checked;

- owner and next review date.

References do not need to occupy the active intervention screen. They may appear in an optional Learn Why view.

## 10. Visual system standard

Every intervention defines four connected visual properties.

### 10.1 Signature material

One dominant material or environmental language, such as glass, water, parchment, stone, pearl light, smoke or radio frequency.

### 10.2 Motion verb

One primary transformation that expresses the mechanism, such as expand, release, clarify, balance, pass, cross, reduce, lock, seal or fade.

### 10.3 Spatial behaviour

The interface must specify how attention moves:

- inward or outward;

- centre to perimeter;

- fragmented to unified;

- near to distant;

- heavy to light;

- open to contained.

### 10.4 Completion state

The final visual state reflects what the user actually did without implying a clinical result. It may show a direction chosen, a step revealed, a thought organised, a window created or content contained.

### Visual discipline

- One dominant focal object per active screen.

- Decorative movement must not compete with the task.

- Meaning cannot rely on colour alone.

- Do not show false data, maps, body measurements or environmental precision.

- Do not use celebratory particles when the mechanism calls for quiet agency.

- Avoid repeating dark teal and gold as the complete identity of every intervention.

- Goal families guide atmosphere while signature systems provide distinction:

| Goal | Atmospheric behaviour |
|---|---|
| Calm | Soft, low-demand and progressively settled |
| Lift | Warmer, brighter and increasingly expansive |
| Ground | Tactile, spatial and environmentally oriented |
| Focus | Precise, architectural and visually reduced |
| Sleep | Ultra-low luminance, finite and progressively disappearing |

## 11. Motion and haptic standard

Motion communicates state change. It is never included only to make the interface feel premium.

Required rules:

- motion begins from the state the user selected;

- duration and direction remain consistent with the mechanism;

- no uncontrolled flashing, rapid zoom, camera shake or surprise movement;

- continuous loops are limited to the period in which they actively guide the user;

- reduced-motion mode conveys the same state change through static frames or restrained fades;

- haptics confirm user action or guide rhythm but never become required for comprehension;

- haptics can be disabled independently.

Any drag, hold, trace, swipe or motion-controlled action needs an equally visible tap alternative.

## 12. Audio and narration standard

Each intervention defines:

- whether sound is essential or optional;

- the purpose of the background track;

- narration density and pacing;

- cue and completion sounds;

- haptic relationship;

- mute, volume and caption behaviour;

- what happens when device audio is unavailable.

Universal requirements:

- predictable start at a conservative volume;

- immediate pause, stop and mute access;

- narration ducks the background track;

- no sudden peaks, startling transitions or hidden autoplay;

- no triumph cue when the user reports no improvement;

- captions or equivalent written guidance;

- no audio-only safety information.

Sleep content additionally requires a visible stop point, background/lock-screen behaviour and autoplay off by default.

## 13. Language and narration standard

Mentication speaks with warmth, confidence and restraint.

Use:

- short concrete sentences;

- one instruction at a time;

- permission rather than pressure;

- language that preserves uncertainty;

- descriptions of what the user can notice or choose.

Avoid:

- forced positivity;

- clinical jargon inside the active experience;

- claims that the app knows what the user feels;

- moral language about avoidance, productivity or completion;

- excessive reassurance;

- infantilising encouragement;

- dramatic promises of transformation.

Preferred pattern:

1. orient;

2. give one instruction;

3. allow silence;

4. validate multiple outcomes;

5. offer the next choice.

## 14. Accessibility standard

Accessibility is part of the primary design, not a simplified fallback.

Every intervention must support:

- Dynamic Type or equivalent text scaling without clipping;

- screen-reader labels and meaningful focus order;

- large targets and adequate spacing;

- sufficient text and control contrast in every state;

- non-colour indicators for selection and progress;

- captions or written equivalents for narration and cues;

- independent audio and haptic controls;

- reduced motion;

- a tap alternative for gesture-dependent interaction;

- one-handed and low-motor-demand use where practical;

- interruption and resume behaviour;

- clear exit and recovery from accidental input.

Body-based interventions also provide a non-illustrated body-part list. Sensory interventions allow unavailable senses to be skipped or substituted without marking the user incomplete.

## 15. Shared interaction shell

The expressive centre may change completely, but these controls remain structurally consistent:

- back or exit;

- pause and resume;

- mute and captions;

- reduced guidance or more guidance;

- accessibility settings;

- this is not helping;

- stop now;

- save or finish;

- support handoff when relevant.

Placement, labels, target sizes and behaviour should remain consistent enough to be usable under stress. The shared shell should recede visually without disappearing functionally.

## 16. Production asset standard

Final generation produces implementation assets, not completed phone screenshots.

Required deliverables where relevant:

- clean background plate;

- transparent signature object;

- foreground and depth layers;

- glow, shadow, particle and mask layers;

- start, active, changed and completion states;

- light/dark or contrast variants where required;

- reduced-motion still;

- seamless motion source or animation specification;

- no-text hero art for the library;

- sound effects as separate files;

- documented crop, safe area, aspect ratio and intended scaling behaviour.

Text, controls, progress indicators and personalised content remain native interface elements. Raster artwork must not contain critical text or controls.

Before coding, every asset is tested at the smallest supported viewport and with long text, large type and reduced motion.

## 17. Reusable design-system requirement

Each flagship must leave behind a reusable engine rather than one bespoke experience.

The engine specification defines:

- inputs;

- state variables;

- decision rules;

- interaction loop;

- visual-state mapping;

- audio-state mapping;

- completion states;

- handoff outputs;

- memory events;

- accessibility substitutions.

A new intervention should be able to reuse the engine while changing content, metaphor and configuration rather than copying the flagship screen by screen.

## 18. Quality gates

### Gate 1 — Therapeutic integrity

- [ ] The intended state and intended change are specific.
- [ ] The active mechanism is identifiable on every screen.
- [ ] Psychoeducation is accurate, restrained and no more than two lines.
- [ ] Completion does not require improvement.
- [ ] No outcome is forced positive.

### Gate 2 — Safety and agency

- [ ] Relevant suitability checks occur before the mechanism.
- [ ] Unsafe or poor-fit states have an appropriate route.
- [ ] The user can skip, adapt and stop.
- [ ] AI suggestions remain editable and rejectable.
- [ ] No psychological inference is presented as fact.

### Gate 3 — Sequence quality

- [ ] The core mechanism begins within approximately ten seconds where safe.
- [ ] Each screen has one primary job.
- [ ] Setup questions change the route.
- [ ] The sequence has no unnecessary explanation or duplicate confirmation.
- [ ] Immediate, Standard and Supported routes are considered.

### Gate 4 — Distinctive experience

- [ ] Signature material is defined.
- [ ] Motion verb expresses the mechanism.
- [ ] Spatial behaviour is coherent.
- [ ] The experience is recognisable without its title.
- [ ] The visual world remains recognisably part of Mentication.

### Gate 5 — Honest adaptation

- [ ] Feedback is mechanism-specific.
- [ ] Memory inputs and claims are defined.
- [ ] User correction and deletion are supported.
- [ ] Low-confidence or insufficient-data states are honest.
- [ ] Handoffs preserve only relevant, consented information.

### Gate 6 — Accessibility

- [ ] Reduced-motion equivalent exists.
- [ ] Silent and captioned routes exist.
- [ ] Gesture-only actions have tap alternatives.
- [ ] Contrast, text scaling and screen-reader flow pass review.
- [ ] Accessibility does not remove the intervention’s core mechanism.

### Gate 7 — Production readiness

- [ ] Canonical flow and copy are approved.
- [ ] Visual states map to functional states.
- [ ] Assets are layered and free of baked-in UI.
- [ ] Audio and motion behaviour are specified.
- [ ] Edge cases, interruption and resume are defined.
- [ ] The reusable engine contract is complete.

An intervention is **Elite Approved** only when all applicable gates pass.
