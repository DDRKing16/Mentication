Priority diagnosis and ownership
1. Entry: ten equal-weight need choices obscure the selected recommendation,
   which appears below the whole list. Own src/pages/NeedStart.jsx.
2. Library: three destination blocks plus search and two filter rows precede
   the practices. Small cards truncate the activity descriptions. Own
   src/pages/InterventionLibrary.jsx.
3. Plan: opaque labels hide the suggested activities. Explanations compete
   with the primary action; empty history copy implies a guaranteed effective
   result after completion. Own src/pages/MyPlan.jsx.
4. Return: saved freeform cues have a delete action but no practice re-entry;
   the empty state is dominated by six notebook links without actual records.
   Own src/pages/ReturnPoints.jsx.
5. Completion: the optional note offers little help turning an experience
   into a usable reminder. Own JourneyTakeaway presentation and its existing
   CSS selectors only.

Implemented
- Four clear starting domains retain all ten original need-to-practice
  mappings. Select a specific need, see its actual branded practice, reason,
  activity and duration together, then enter the existing flow. Browser Back,
  refresh and heading focus work across the chooser's stages.
- Library foregrounds practice selection. Setting/time filters expand on
  request. Search/category/filter state survives reload, result counts and
  clear-all make empty results recoverable. Action descriptions cover all
  19 catalogue entries; they describe doing, not guaranteed benefits.
  Approved atmosphere colours and supplied logo assets are retained. Card
  descriptions use full width, including at larger text sizes.
- My Plan reveals the activities and durations inside a proposed sequence;
  the time/history explanation is available beside it. Lift still starts a
  fresh check-in. Current feelings are not inferred from history. This uses
  the existing recommendation engine, with no scoring changes. Plan refreshes
  on return, focus and session-change events. It has loading/error states.
- Return points distinguishes explicit reminders/reflections from notebooks.
  Kept words have a readable typographic hierarchy, a date when valid, and
  a direct practice re-entry action. Empty state explains how to save a cue.
  Existing care/Tara/thought records and storage/deletion handlers are kept.
- Completion invites an optional concrete "When… I could…" cue. The prompt is
  a placeholder, never a prefilled answer. Save/update/delete semantics stay
  explicit, and unsaved-text/device-only limitations remain visible.
- Scoped paper/emerald surfaces, serif hierarchy and restrained arch markers
  connect these shared screens. Dark/high-contrast modes, keyboard focus and
  reduced-motion behavior are supported. No new animation dependency.

Qualitative review (judgment, not a measured score)
Visual craft: shared pages now use consistent spacing, type, material and
hierarchy while preserving the distinct practice worlds and Home artwork.
Practice quality: previews explain the concrete action; optional cues invite
reuse in a real moment. Core remaining practice mechanics are not redesigned
in this bounded increment.
Personalization: the source and contents of a suggestion are inspectable;
a user can choose a current need instead. No new inferred diagnosis/outcome.
Engagement: the path from Home's Guide me to a practice, and from a kept cue
back to its practice, is continuous and explicit.
Cognitive burden: staged choice removes the ten-option wall, filter disclosure
keeps the Library focused, and unused notebooks no longer dominate empty return.
Mobile/accessibility: 320/390px rendered review, 150% root text at 320px,
keyboard chooser, reduced motion and dark screenshots. Larger-text inspection
led to the full-width Library description refinement.
Reliability: browser checks establish navigation/storage behavior; they do not
establish clinical effectiveness, preference, or a "2x" quality increase.
